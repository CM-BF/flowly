### Retained minimal change: observer notification boundaries

Existing opt-in timing spans show own render work below3ms but drawer/progress/workpad render-to-effect windows80–126ms and about7 renders/10s while board reads return same data. These spans include subtree/commit/effect delay and are not function-level CPU samples. Two source causes are observable: the direct-card useBoardQuery wrapper spreads the tracked query result, subscribing consumers to fetch-state properties they never read; the same scoped spread also makes TaskDrawer's polling-only observer track all those properties. In the old non-scoped path the wrapper implicitly read data, so it did not have an empty tracked set. After removing that eager read, the ignored polling result needs explicit silence to avoid TanStack's empty-tracked-set default notifying on all state changes.

Replace the scoped fallback spread with a transparent tracked view: lazily override data with preferFullBoard and isPending with the existing fallback rule; preserve all other getters, methods, property enumeration and errors without eagerly accessing them. Keep the query cache/etag untouched. Expose the standard notifyOnChangeProps option and give only TaskDrawer's poll-only observer an empty notification list. Poll timing/fetches continue; the mounted root/data consumers still receive changed boards and drive fresh task/project/event props, including deletion. Authorization and direct navigation retain fresh reads. Tests must use real QueryObservers for same-data fetch no-notify, changed-data notify to independent consumers, fallback revision/pending/error/method/enum behavior. No new query or delayed ownership decision.
