# i18n verification (2026-10-16)

Method: headless Chromium (Playwright 1.63, isolated context, `local-network-access` granted only to `https://app.paseo.sh`) against the running daemon and the `Tinylink` demo project; the browser locale drives "Device language". The host sidebar is cropped out of screenshots. No native Paseo window was used.

## Completed

| Check | Result |
| --- | --- |
| `npm run typecheck` | pass |
| `npm test` | pass (62 files, 383 tests; includes 9 catalogs × 4 completeness checks) |
| Plugin reloaded (`paseo plugin reload paseo-ultra-kanban`), no page errors | pass |
| Device language `ja-JP`, `de-DE`, `ru-RU`, `zh-CN`: board renders translated chrome, lanes, chips, relative times; agent-written card text stays as written | pass ([ja](../promo/screenshots/i18n/ja-JP-board.png)) |
| Settings → Language picker: choose 한국어, board switches at once; set back to "Device language", board returns to English | pass |
| Settings read before the setting was registered: surface fell back to the device language without crashing | pass (found and fixed: `languageSettings` was not registered in `index.server.ts`) |
| No `t()` call is evaluated at module load | pass (AST scan) |

## Unrun

- Phone/tablet layouts and the native apps (text length in compact layouts, Android/iOS `Intl` availability). Hermes without `Intl` falls back to English by design (`deviceLocale` catches).
- Every screen in every language (insights, ideas, drawer, dialogs) was reviewed in the catalogs, not visually. Long German/Russian strings may truncate in tight rows.
- Translation quality was not reviewed by native speakers.
- Live switching of the Command Center titles (registered once at load).
